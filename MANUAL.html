MobileBandCheckup — full manual

A standalone RouterOS scripting suite for MikroTik routers that monitors LTE/NR (5G NSA) band changes and signal quality on a modem interface, logging every meaningful transition to the system log and persisting comparison state across reboots. This manual covers every script, every global, every tunable with its default and range, the scheduler entries and required policies, the state file, the operator commands, and how to verify a deployment.

revision mbc3-final-20260602-save-helper-revert aligned with routeros_bundle b2.22 hardware test 2026-05-31 18:41 UTC reboot routeros 7.21.4 device MikroTik Chateau 5G R17 AX modem Quectel RG650E-EU
Status — confirmed working on hardware (transitively). MobileBandChange3.rsc and mbc3-restore-state.rsc are byte-for-byte equivalent on executable lines to the routeros_bundle b2.22 sources that were verified working at the 2026-05-31 18:41 reboot — with one additional safety guard: each of the four /file remove calls in the inline state-save blocks is wrapped in :if ([:len [/file find name=$sf]] > 0) so the first save on a fresh install can never enter the no-such-item on-error path. The installer registers script and scheduler policies identical to the bundle's tested scheduler_templates.rsc. The installer / setup / cleanup wrappers are MobileBandCheckup-original code.

Overview & architecture

The main script (MobileBandChange3) runs every minute via the RouterOS scheduler. Each run it polls the LTE interface monitor, extracts the current radio conditions (band, carrier-aggregation set, RSRP, SINR, CQI, RI, MCS, NR fields), compares them against the last-known state, and logs any meaningful change. It is silent when nothing changes — except for a periodic heartbeat.

State is persisted to a single flat file, /file mbc3-state.txt, written inline by MobileBandChange3 at each designated exit point. On boot, mbc3-restore-state reads it through an allow-list guard and reloads the globals so the post-reboot comparison resumes where the pre-reboot one left off.

The suite is five files; only four are registered as /system script objects (the installer is import-only):

Install / upgrade / uninstall

Fresh install

Upload the five .rsc files to the router flash (e.g. via WinBox Files drag-and-drop, or scp to /), then:

/import file-name=mbc3-install.rsc

The installer registers the four scripts and the two scheduler entries with their required policies (policy table). State file mbc3-state.txt is created automatically on the first save — no install step required. Source .rsc files can be removed from flash after install; everything runs from NVRAM scripts.

Upgrade from a pre-bundle-aligned revision

The installer also removes the legacy mbc3-restore script and the mbc3-main scheduler if present, so upgrades end up with a single, clean set of names matching the bundle (mbc3-restore-state + mbc3-run). Simply re-run the import; no manual cleanup needed.

Update schedulers only (no script changes)

/system script run mbc3-setup

Idempotent; safe to re-run. Also removes the legacy scheduler names.

Uninstall — dry-run first

mbc3-cleanup is dry-run by default so an accidental invocation cannot wipe a working deployment. With no commit flag set it logs what it would remove and counts entries; nothing is deleted.

/system script run mbc3-cleanup
/log print where message~"mbc3-cleanup"

Uninstall — apply

:global mbc3CleanupCommit
:set mbc3CleanupCommit true
/system script run mbc3-cleanup

The flag auto-clears at the start of a committed run, so a later stray invocation falls back to dry-run. The cleanup removes both schedulers, all four registered scripts, the state file, all mbc3* globals, and legacy artefacts (mbc3-restore, mbc3-main, mbc3-save, mbc3-state script slot) from earlier revisions.

To remove mbc3-cleanup itself afterwards: /system script remove [find name=mbc3-cleanup]

RouterOS gotchas (issues that bit us)

Bug (fixed) — [:find] guards Earlier revisions used [:find …] = nil, which is false-not-nil, so the guards never fired and arithmetic / :pick ran on false whenever a modem field was absent (no CA, NR inactive). Fix: every site now uses [:typeof …] = "num".
Bug (fixed) — bare-name scheduler on-event A scheduler with on-event :delay 50s; MobileBandChange3 (bare name after the delay) is parsed as a command and fails with expected command name (line 1 column …). Fix: the scheduler now uses :delay 50s; /system script run MobileBandChange3; confirmed firing after a reboot.
Bug (fixed) — mbc3-main → mbc3-run The periodic scheduler was renamed for consistency with the upstream bundle. Both mbc3-install and mbc3-setup remove a leftover mbc3-main on upgrade so MobileBandChange3 can't run twice per minute.
Bug (fixed) — script ↔ scheduler policy mismatch RouterOS refuses to run a scheduled script when the scheduler's policy does not exactly match the script object's policy ("not enough permissions to run script"). Without ftp on MobileBandChange3, the inline state save throws "inline state save failed"; without test, /interface lte monitor fails. Fix: the installer now passes explicit policy= on every add / set and the script and its scheduler always carry identical policy strings (policy table).

MobileBandChange3 — band & quality monitor

scheduler mbc3-run — startup, interval 1m, :delay 50s policy ftp,read,write,policy,test state file mbc3-state.txt interface lte1

Reads the modem's primary band, carrier-aggregation set, and LTE/NR signal quality (/interface lte monitor), logs band/CA changes as events and a periodic heartbeat, and persists comparison state. The startup guard runs mbc3-restore-state inline before reading persisted options if the boot scheduler hasn't won the race.

Key design decisions

  • Scheduler race guard. On boot, mbc3-restore-state and mbc3-run both start at startup (the latter delayed 50s). If mbc3-run somehow wins the race, the very first thing it does is check mbc3RestoreDone; if unset, it runs mbc3-restore-state inline before reading any persisted state, so defaults can never overwrite restored values.
  • 2-run debounce on signal quality. RSRP and SINR tier transitions only log when the new label is observed on two consecutive runs. Suppresses log noise from signals hovering near a tier boundary.
  • CA normalization. Carrier aggregation lists from the modem can contain exact duplicates or vary in ordering without a real composition change. normalizeCA removes duplicates (preserving first-seen order) before comparison, so only genuine set changes produce ca-composition-change events. Ordering / representation-only differences produce the lower-severity ca-raw-change event.
  • Primary-change classification. When the primary cell changes, the script extracts band, EARFCN, and PCI from the primary-band string and labels the event band-change / earfcn-change / phy-cellid-change / details-change based on which field actually changed.
  • Crash-forensics probe. Every significant step updates three globals (mbc3Probe, mbc3ProbeDetail, mbc3FailProbe). At the start of each run, the previous values are snapshotted into mbc3LastRunProbe*. If the script dies mid-run, the next run captures where it was. Query with :put $mbc3LastRunProbe, etc.
  • Monitor validity guard. If /interface lte monitor returns no primary-band, the script logs LTE monitor-invalid with a list of missing fields, resets mbc3LogInited so the next valid reading re-runs the init path, and skips the comparison.
  • Interface-down recovery. When lte1 stops running, the script logs LTE iface-down, fully resets comparison state, and saves. When it comes back, LTE iface-up-recovery is logged and the next valid reading emits a fresh LTE init.

mbc3-restore-state — boot-time state restore

scheduler mbc3-restore-state — startup once (interval 0) policy ftp,read,write,policy reads mbc3-state.txt

Runs once on boot. Reads /file mbc3-state.txt, validates it, and replays it via [:parse] so the persisted globals are back in RAM before MobileBandChange3 compares anything. The same script is also invoked inline by MobileBandChange3 if it discovers mbc3RestoreDone is still unset (scheduler race guard).

Validation pipeline

  1. File presence: missing → cold start (no state).
  2. Size bounds: < 80 bytes → cold start; > 60 000 bytes → refused (DISRUPTIVE).
  3. Markers: require # MBC3-STATE-V1 at the start and # MBC3-STATE-END at the end. Either missing → cold start.
  4. Allow-list guard: every line is checked. Allowed forms:
    • A # comment line.
    • :global <name> where <name> is one of the 14 known persisted variables.
    • :set <name> <value> where <value> is either empty, a bare scalar of [0-9a-zA-Z._-], or a single quoted string whose only unescaped " is the final character.
    Anything else — an embedded \r, an unescaped $, a value with unexpected characters, an unknown variable name, a non-assignment / non-comment line — fails the check and the file is rejected (cold start). Only after the guard passes does the script [:parse] and execute the payload.

Allow-listed variables

mbc3Debug, mbc3DebugRaw, mbc3HeartbeatEvery, mbc3QualityMonitor, mbc3LastPrimary, mbc3LastCA, mbc3LastCARaw, mbc3LastLRsrp, mbc3LastLSinr, mbc3LastNrActive, mbc3PendingLRsrp, mbc3PendingLRsrpCount, mbc3PendingLSinr, mbc3PendingLSinrCount.

Adding a new persisted global means three touch points: declare and :global it in MobileBandChange3.rsc, add it to the mbc3BuildState helper (so it gets written), and add it to the allow-list table inside mbc3-restore-state.rsc (so it survives the guard on the next boot). Skipping the allow-list update means the restore silently cold-starts.
Bug (fixed) — every-reboot cold start from = nil An earlier version of the line tokenizer compared [:find $rest "\n"] to the bare identifier nil, which is unreliable in RouterOS: the comparison silently corrupted the line and every reboot took the cold-start path. Fix: every [:find …] result is tested via [:typeof …] = "num", never against nil.

mbc3-install — bootstrap installer

invocation /import file-name=mbc3-install.rsc not a registered script

Reads the other four .rsc files from flash, registers each as a /system script object with the correct policy, and adds the two scheduler entries. Idempotent — re-running upserts (try add, fall back to set [find name=…] inline). Includes a legacy migration step so upgraders from a pre-bundle-aligned revision end up with the new names.

What it does, in order

  1. Legacy removal. If a mbc3-main scheduler exists, remove it (replaced by mbc3-run). If a mbc3-restore script exists, remove it (replaced by mbc3-restore-state).
  2. Register scripts with explicit policies via the upsertScript helper. The helper checks the source file exists, reads it, sanity-checks the length against a minimum, and then tries add first and falls back to set [find name=…] if the object already exists.
  3. Register schedulers with explicit policies via the upsertScheduler helper. mbc3-restore-state at startup with interval 0; mbc3-run at startup with interval 1m and the :delay 50s stagger.

Required source files on flash

FileMin bytesRegistered as
MobileBandChange3.rsc20000MobileBandChange3
mbc3-restore-state.rsc300mbc3-restore-state
mbc3-setup.rsc500mbc3-setup
mbc3-cleanup.rsc500mbc3-cleanup

If a file is missing or shorter than its minimum, the installer logs an error and skips that object — it never registers a truncated script.

Upsert safety. Every set uses set [find name=<literal>] inline. Never store a find-result ID in a variable and pass it to set: if the find returned empty, the stored ID is empty and set is applied to all entries — a real foot-gun in RouterOS.

mbc3-setup — scheduler refresh

invocation /system script run mbc3-setup or /import file-name=mbc3-setup.rsc policy read,write,policy

Registers or updates scheduler entries only — does not touch script source. Safe to run at any time, idempotent, requires no .rsc files. Use it when you want to refresh the scheduler config without re-importing the installer (e.g. after modifying a scheduler's on-event by hand and wanting to revert it).

Also performs the same legacy-removal step (mbc3-main, mbc3-restore) so a partial migration can be completed without re-running the full installer.

mbc3-cleanup — uninstaller (dry-run by default)

invocation /system script run mbc3-cleanup policy ftp,read,write,policy commit flag mbc3CleanupCommit

Symmetric to mbc3-install. Removes everything the installer added, plus in-RAM globals and legacy artefacts from earlier revisions.

Dry-run by default — mirrors the routeros_bundle bundle-reset-state safety pattern. With no commit flag set, every step logs what it would remove and counts entries; nothing is actually deleted. The flag auto-clears at the start of a committed run so a later stray invocation falls back to dry-run.

Operator flow

# Dry-run first
/system script run mbc3-cleanup
/log print where message~"mbc3-cleanup"

# Apply
:global mbc3CleanupCommit
:set mbc3CleanupCommit true
/system script run mbc3-cleanup

What it removes, in order

  1. Schedulers first, so neither mbc3-restore-state nor mbc3-run can fire between us deleting their script bodies and finishing. Current names: mbc3-run, mbc3-restore-state. Legacy names: mbc3-main, mbc3-restore.
  2. Scripts. Current: MobileBandChange3, mbc3-restore-state, mbc3-setup. (Cleanup deliberately leaves itself in place so a re-run is possible; remove it by hand afterwards.) Legacy: mbc3-restore, mbc3-save, mbc3-state script slot from the pre-file-state architecture.
  3. State file /file mbc3-state.txt.
  4. All mbc3* globals from /system script environment via remove [find where name~"^mbc3"]. Removing entries from environment is what unsets in-place — :set var without a value would only blank, not free the slot.

Schedulers

All script-invoking schedulers use /system script run <name> (a bare name fails with expected command name). A scheduler's policy must equal the script object it runs, or RouterOS refuses with not enough permissions to run script.

Schedulerstartintervalon-eventpolicy
mbc3-restore-statestartup0 (once)/system script run mbc3-restore-stateftp,read,write,policy
mbc3-runstartup1m:delay 50s; /system script run MobileBandChange3ftp,read,write,policy,test

The 50-second startup delay on mbc3-run mirrors the bundle's tested template — it lets the modem settle past its boot-time partial-data window before the first poll, which reduces monitor-invalid noise in the early-boot log.

Without ftp on MobileBandChange3, every save ends in the on-error block and logs "inline state save failed". Without test, the modem read returns an empty array and you get an unending stream of monitor-empty. These are project invariants — don't strip them.

State file

path /file mbc3-state.txt format parse-replay code with markers size bounds 80 ≤ bytes ≤ 60 000

The state file is generated, validated, written, and read by the suite — never edit it by hand. Format:

# MBC3-STATE-V1
:global mbc3Debug
:set mbc3Debug false
:global mbc3DebugRaw
:set mbc3DebugRaw false
:global mbc3HeartbeatEvery
:set mbc3HeartbeatEvery 60
:global mbc3QualityMonitor
:set mbc3QualityMonitor false
:global mbc3LastPrimary
:set mbc3LastPrimary "b3@10MHz earfcn: 1444 phy-cellid: 207"
:global mbc3LastCA
:set mbc3LastCA "b3 ; b1"
:global mbc3LastCARaw
:set mbc3LastCARaw "b3 ; b1"
:global mbc3LastLRsrp
:set mbc3LastLRsrp "good"
:global mbc3LastLSinr
:set mbc3LastLSinr "good"
:global mbc3LastNrActive
:set mbc3LastNrActive false
:global mbc3PendingLRsrp
:set mbc3PendingLRsrp ""
:global mbc3PendingLRsrpCount
:set mbc3PendingLRsrpCount 0
:global mbc3PendingLSinr
:set mbc3PendingLSinr ""
:global mbc3PendingLSinrCount
:set mbc3PendingLSinrCount 0
# MBC3-STATE-END

Strings are quoted, with \, ", and $ escaped by the escapeStr helper inside MobileBandChange3. The mbc3-restore-state allow-list guard rejects any line outside this exact shape — see the validation pipeline.

Save write sequence (every designated exit point):

  1. Build the payload via mbc3BuildState.
  2. /file remove [find name="mbc3-state.txt"] — old file gone (tolerated if absent).
  3. /file print file="mbc3-state.txt" — creates the file empty.
  4. :delay 200ms — settle time so the new file is visible.
  5. /file find name="mbc3-state.txt" — re-locate the new file id.
  6. /file set $id contents=$payload — write the body.
  7. Read back, check that # MBC3-STATE-END is present in the contents.

The whole block is wrapped in :do { … } on-error={ … } so a failure logs a warning and the next save retries from scratch — there is no partial-file state.

Reset state without uninstalling

There is no dedicated reset helper. To force a cold start without removing the scripts:

/file remove [find name="mbc3-state.txt"]
/system script environment remove [find where name~"^mbc3"]
/system script run MobileBandChange3

Switch heartbeat cadence

:global mbc3HeartbeatEvery
:set mbc3HeartbeatEvery 30   # ~30 min with a 1-min scheduler
# value will be persisted by the next state save

On-router smoke test (post-install)

  1. Import the installer: /import file-name=mbc3-install.rsc
  2. Confirm objects exist with the right policy: 
    /system script print detail where name="MobileBandChange3"
/system scheduler print detail where name="mbc3-run"
    Policy field on both must be ftp,read,write,policy,test.
  3. Trigger a run by hand and look for LTE init: 
    /system script run MobileBandChange3
/log print where message~"LTE init"
  4. Verify the state file was created: 
    /file print where name="mbc3-state.txt"
/file get [find name="mbc3-state.txt"] contents
    Must end with # MBC3-STATE-END.
  5. Reboot and verify the restore wins the race (or the inline restore-guard saves the day): 
    /system reboot
# after reboot:
/log print where message~"\\[mbc3-restore-state\\] state restored"
